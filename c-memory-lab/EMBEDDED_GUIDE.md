# 嵌入式 C 扩展讲义（25～46）

## E. 嵌入式 C 深化

### 25 内存段

STM32 程序通常把代码和常量放在 Flash，把运行时可写数据放在 SRAM。已初始化全局/静态对象属于 `.data`，零初始化对象通常属于 `.bss`；局部自动对象通常使用栈，动态分配通常使用堆。具体布局由链接脚本决定，地址打印只是观察，不能代替 map 文件。

### 26 启动与链接

复位后 `Reset_Handler` 设置栈、复制 `.data`、清零 `.bss`、执行系统初始化并进入 `main`。所以全局对象在 `main` 第一行前已经具备规定初值。启动文件、链接脚本和 C 运行时共同建立 C 程序环境。

### 27 寄存器读改写

`REG |= mask` 通常是读、修改、写回三步。普通控制寄存器可能适用，但写 1 清零、只写、硬件异步改变或包含保留位的寄存器必须遵循手册规则。优先使用芯片提供的原子置位/清零寄存器或专用 HAL/LL API。

### 28 位运算安全

移位前先使用无符号、宽度明确的类型；移位量不得大于等于类型位数。设置字段时先清目标掩码，再写入裁剪后的字段。`1 << 31` 可能涉及有符号溢出，`UINT32_C(1) << 31` 意图更明确。

### 29 ISR 共享状态

`volatile` 防止编译器省略访问，但不保证原子性、顺序或“检查并清除”不被中断打断。单个位标志也要明确生产者/消费者；复合状态应使用临界区、原子操作、队列或任务通知。

### 30 DMA 生命周期

DMA 是在 CPU 函数返回后仍可能继续访问内存的硬件主设备。缓冲区必须从启动传输一直有效到完成/取消确认。局部自动数组离开作用域后失效，不能继续交给 DMA。还需避免 CPU 与 DMA 无同步地同时修改缓冲区。

### 31 固定内存池

固定池用确定 RAM 换取确定的分配时间和无碎片行为，适合消息、包和控制块。必须处理池满、重复释放和非法指针。它不是自动安全，仍要定义所有权和并发保护。

### 32 Tick 回绕

无符号整数按模回绕。超时判断使用 `(uint32_t)(now - start) >= duration`，只要持续时间小于可区分的半范围，就能跨越回绕工作。不要比较 `now >= start + duration`。

## F. UART 纵向主线

### 33 字节流

UART 只传递连续字节，不知道“命令”或“帧”。一次 HAL/DMA 回调的长度不等于协议消息边界；一帧可能跨多次接收，多帧也可能一次到达。

### 34 SPSC 环形缓冲区

单生产者单消费者缓冲区让 ISR 快速投递、主循环慢慢处理。必须定义空/满条件和溢出策略。示例浪费一个槽位区分空满；真实 ISR 并发下还要根据 MCU 原子访问能力和编译器内存模型处理可见性。

### 35 流式状态机

解析器把状态保存在对象中，每收到一个字节推进一次，因此能处理半包。容量必须为结尾 `\0` 留空间；超长输入后要丢弃或重新同步，不能把下一条合法命令拼进坏数据。

### 36 帧与校验

帧头用于同步，长度限制边界，命令区分行为，校验检测传输错误。简单累加和只适合教学，工程可根据风险使用 CRC。编码函数必须同时接收输出容量并返回实际长度。

### 37 错误重同步

解析错误不能让状态机永久卡住。长度非法、校验失败或噪声后回到等待帧头；要考虑错误字节本身是否可能是下一帧帧头。同步策略应通过连续坏帧后接正确帧测试。

### 38 DMA 交接

双缓冲允许 DMA 写一块、CPU 处理另一块，但消费者过慢时两块都可能占用。必须定义 ready/owned 状态、溢出计数和覆盖策略。DMA 只解决搬运，不解决消息边界和协议解析。

### 39 命令分发

表驱动分发把命令号映射到回调，新增命令无需修改分发器。回调必须验证 payload 长度和数值范围；`void *context` 提供业务状态，但生命周期必须覆盖调用。

### 40 超时与统计

通信系统需要统计接收字节、有效帧、校验错误、溢出和超时。没有统计就无法区分“没发生”和“发生后被丢弃”。重试必须有限，并配合退避、降级或故障状态。

## G. 可测试嵌入式工程

### 41 HAL 接口隔离

业务依赖小接口而不是直接依赖 `UART_HandleTypeDef`。主机实现写到 `FILE`，STM32 实现调用 HAL；业务层保持不变。接口文档要说明阻塞性、超时、上下文和调用场景。

### 42 Fake 设备

Fake 是可编程的替身，可返回预设数据、指定次数失败或模拟断线。它让状态机和错误恢复在没有开发板时自动测试，但不能替代真实电气和时序验证。

### 43 主机测试

纯 C 状态机、协议和缓冲区可以用 `assert` 或测试框架在 Mac 上运行。测试应覆盖正常路径、边界、非法输入和所有状态/事件组合。硬件适配层保持薄，减少只能上板验证的代码。

### 44 断言与错误码

断言用于“程序员本应保证但违反了”的不变量，生产环境可能关闭；错误码用于设备缺失、超时、空间不足等运行时可恢复情况。不要用断言替代外部输入检查。

### 45 配置与日志

引脚、容量、波特率和超时使用有意义的配置名，避免魔法数字。日志提供等级并可编译期开关；ISR 和高频路径不要阻塞打印。日志应帮助定位状态和错误，而不是淹没有效信息。

### 46 内存预算

RAM 预算至少包含静态数据、主栈、RTOS 堆、任务栈和安全余量。静态数据从 map 文件获取，任务栈结合高水位实测。总量小于芯片 SRAM 不代表安全，还要考虑峰值、库和中断嵌套。
