# 从通用 C 到 STM32

本文件连接 `c-memory-lab` 和同级的 `../stm32-embedded-roadmap`。

## 两套课程的职责

```text
c-memory-lab
├── 在 Mac 上观察内存、编译器和纯 C 行为
├── 让协议、状态机和缓冲区可自动测试
└── 不依赖开发板

stm32-embedded-roadmap
├── CubeMX/HAL、时钟、引脚和外设
├── 调试器、串口、逻辑分析仪和真实故障
└── 把纯 C 核心接到 STM32 中断/DMA/RTOS
```

## 知识映射

| C 课程 | STM32 场景 |
|---|---|
| 01～07 内存模型 | 栈、DMA 缓冲区、HAL 句柄、任务栈 |
| 08～15 语言与回调 | HAL 回调、状态枚举、寄存器掩码 |
| 16～21 工程化 | BSP、错误码、环形缓冲区、状态机 |
| 22～24 嵌入式桥梁 | 协议字节序、`volatile`、驱动接口 |
| 25～32 嵌入式深化 | 启动、内存段、ISR、DMA、Tick |
| 33～40 UART 纵线 | UART IRQ/DMA、协议与故障恢复 |
| 41～46 测试工程 | Fake HAL、主机测试、RAM 预算 |

## UART 端到端结构

```text
STM32 UART 引脚
  ↓
USART 外设
  ↓
IRQ 或 DMA（STM32 项目）
  ↓
uart_device_feed（纯 C 核心）
  ↓
环形缓冲区
  ↓
帧解析状态机
  ↓
命令回调
  ↓
业务接口/Fake 或真实 BSP
```

核心规则：硬件层只负责取得字节和报告时间，纯 C 层负责协议和业务状态。不要在 UART ISR 中直接解析完整命令。

## 移植步骤

1. 在 Mac 上运行 `make uart-core`，确认所有测试通过。
2. 将项目 `include/` 和 `src/` 加入 STM32 工程。
3. 在 UART 中断/DMA回调中把新字节送入核心输入接口。
4. 在主循环或通信任务调用处理函数。
5. 用板级回调实现 LED/PWM/状态查询。
6. 保留主机测试，STM32 适配层只做薄封装。

## 学习完成标准

你应能回答：

- DMA 正在写哪个对象，这个对象何时失效？
- ISR 和主循环谁生产、谁消费？
- `volatile` 解决了什么，没解决什么？
- 环形缓冲区满时丢新数据还是旧数据？
- 错误帧如何重新寻找帧头？
- 协议层如何在没有 STM32 的情况下测试？
- 换 UART 实例或换 MCU 时，哪些文件不应该修改？
