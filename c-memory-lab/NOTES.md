## 一、printf 格式占位符

### 1.1 `%02x` 是什么意思？（第 8 行 `printf("%02x ", (unsigned int)bytes[i])`）

`%02x` 拆解：
- `%x` — 以十六进制格式输出（小写字母 a-f）
- `02` — 最小宽度 2 位，不足时左边补 0

**举例对比**：

| 字节值（十进制） | `%x` 输出 | `%02x` 输出 |
|:---:|:---:|:---:|
| 10 | `a` | `0a` |
| 255 | `ff` | `ff` |
| 0 | `0` | `00` |

这样每个字节始终显示为整齐的 2 位十六进制数，方便查看内存原始数据。

### 1.2 `%p`、`%zu`、`%c`、`%#x`、`%.2f` 分别是什么意思？（第 20-22 行）

```c
printf("letter     %p   %zu     %c\n",   (void *)&letter, sizeof letter, letter);
printf("number     %p   %zu     %#x\n",  (void *)&number, sizeof number, (unsigned int)number);
printf("decimal    %p   %zu     %.2f\n", (void *)&decimal, sizeof decimal, decimal);
```

| 占位符 | 参数类型要求 | 含义 | 示例输出 |
|--------|-------------|------|----------|
| `%p` | `void*`（必须显式转换） | 以实现定义的格式打印指针值，常见形式类似十六进制地址 | `0x16b0a30f0` |
| `%zu` | `size_t` | 打印 `sizeof` 返回值 | `4` |
| `%c` | `int`（char 会整型提升） | 打印单个 ASCII 字符 | `A` |
| `%#x` | `unsigned int` | 非零值通常带 `0x` 前缀的十六进制；零通常输出 `0` | `0xff` |
| `%.2f` | `double`（float 会提升） | 格式化并四舍五入到小数点后 2 位 | `3.14` |

> **注意**：`%p` 期望的是 `void*`，所以要把 `&letter`（类型是 `char*`）显式转换成 `(void*)`，否则属于未定义行为。

### 1.3 `(void *)&letter` 加这个转换是什么意思？

- `&letter` — 取 letter 的地址，类型是 `char*`
- `(void *)&letter` — 把 `char*` 转成通用的 `void*` 类型

因为 `%p` 严格要求参数是 `void*` 类型，虽然大多数编译器不报错，但类型不匹配在 C 标准中属于未定义行为。加上显式转换可以消除警告，也是标准写法。

## 二、小端序（Little Endian）

### 2.1 为什么 0x12345678 打印出来是 78 56 34 12？（第 7-9 行循环）

因为你的 Mac 是**小端序的 ARM64（Apple Silicon）**架构。

**小端序规则**：最低有效字节（LSB）存在最低内存地址。

```
值:    0x12  34  56  78
       高位            低位（LSB）

内存地址  低  → → → → → → → →  高
存储字节  78      56      34      12
         低位                      高位
```

循环从低地址往高地址读，所以先读到 `78`，然后 `56`、`34`、最后 `12`。

**大小端对比**：

| 架构 | 0x12345678 内存排列 | 代表平台 |
|------|-------------------|---------|
| 小端序 | `78 56 34 12` | x86、x86-64、大多数 ARM |
| 大端序 | `12 34 56 78` | 某些嵌入式处理器、网络字节序 |

### 2.2 为什么是 78 56 而不是 7 8 5 6？

C 中 `sizeof(char) == 1`，一个 `char` 就是一个 C 字节。当前 Mac 上 `CHAR_BIT == 8`，所以一个字节是 8 比特，刚好对应两个十六进制位。`0x78` 是一个完整的 C 字节，不能通过普通指针分别取得 `0x7` 和 `0x8` 的独立内存地址，但可以通过移位和掩码分别提取高、低 4 位：

```c
unsigned char value = 0x78;
unsigned char high = (value >> 4) & 0x0f;  // 0x7
unsigned char low  = value & 0x0f;         // 0x8
```

### 2.3 number = 256 时，为什么是 00 01 00 00？

```
256 = 0x100 = 0x00000100（4 字节 int，高位补零）

内存排列（小端序）：
地址  低 → → → → → 高
字节  00   01   00   00
      LSB           MSB
```

- 字节 0（最低位）：`0x00`
- 字节 1：`0x01`（1 × 256 = 256，进位到这里了）
- 字节 2、3：`0x00`（高位补零）

### 2.4 -1 的十六进制是什么？

在当前机器的 32 位、二进制补码 `int` 表示中，`-1` 的对象表示通常为 `0xFFFFFFFF`，小端序排列为 `ff ff ff ff`。

**原因 — 补码（Two's Complement）**：

```
 1  = 0x00000001
~1  = 0xFFFFFFFE   （按位取反）
+1  = 0xFFFFFFFF   （加一，这就是 -1）

验证：-1 + 1 = 0
0xFFFFFFFF + 0x00000001 = 0x00000000  ✓（进位溢出丢弃）
```

**4 字节 int 值域**（32 位、补码表示下）：

| 值 | 十六进制 | 说明 |
|----|----------|------|
| 2147483647 | `0x7FFFFFFF` | 最大正数 |
| 1 | `0x00000001` | |
| 0 | `0x00000000` | |
| -1 | `0xFFFFFFFF` | 全 1 |
| -2147483648 | `0x80000000` | 最小负数 |

**注意**：最高位为 1 是负数这个规则仅在已知类型是有符号整数、且使用补码表示时才成立。对于 `unsigned int`，`0xFFFFFFFFU` 表示的是 `4294967295`，不是 `-1`。不能拿任意内存的最高位直接判断正负。

## 三、unsigned char* 逐字节读取技巧

### 3.1 循环怎么知道读几个字节？为什么一个地址刚好对应一个字节？

```c
for (size_t i = 0; i < size; ++i) {
    printf("%02x ", (unsigned int)bytes[i]);
}
```

**循环次数**由 `size` 参数决定，调用时传的是 `sizeof number`（int 是 4），所以循环 4 次。

**一个地址一个字节**是因为 `unsigned char*` 的指针步长是 1：

```c
// C 标准规定：sizeof(unsigned char) == 1 恒成立
```

**指针运算公式**：`ptr + i` 的实际地址 = `原始地址 + i × sizeof(指针指向的类型)`

> **注意**：`ptr + i` 只有在 `ptr` 指向某个数组元素、且结果仍在该数组或数组尾后位置时才有定义。不能把指针当普通整数在无关内存之间任意加减。
>
> ```c
> int values[4];
> int *p = values;
> p + 3; // 合法，指向 values[3]
> p + 4; // 可形成尾后指针，但不能解引用
> p + 5; // 未定义行为
> ```

| 指针类型 | `ptr + 1` 跳多少字节 |
|----------|---------------------|
| `int*` | 4 字节 |
| `char*` / `unsigned char*` | 1 字节 |
| `double*` | 8 字节 |

所以把 `&number`（int*）转成 `unsigned char*` 后，`bytes[0]` 读第 1 个字节，`bytes[1]` 读第 2 个字节，每次刚好前进 1 字节。

## 四、十六进制与二进制的关系

### 4.1 为什么查看内存都用十六进制而不是十进制？

因为十六进制和二进制**天然对齐**：

```
在当前 CHAR_BIT == 8 的机器上：
1 字节 = 8 比特
1 个十六进制位 = 4 比特
所以 1 字节 = 2 个十六进制位
```

**对照表**：

| 十六进制 | 二进制 | 十进制 |
|:---:|:---:|:---:|
| `0x0` | 0000 | 0 |
| `0x5` | 0101 | 5 |
| `0xA` | 1010 | 10 |
| `0xF` | 1111 | 15 |
| `0xFF` | 1111 1111 | 255 |

看 `0xFF` 就知道 8 个比特全是 1；看十进制 `255` 完全看不出位模式。所以查看内存原始数据时，十六进制是最直观的选择。

### 4.2 输出前是先转成了十六进制吗？

对，`%02x` 就是告诉 `printf`："把这个整数值用十六进制格式显示"。

```
内存原始数据（二进制）
      ↓
bytes[i] 读出一个字节值（比如 120）
      ↓
%02x 格式化成字符串 "78"
      ↓
屏幕显示: 78
```

同一个值 120，不同格式输出不同：
- `%02x` → `78`（十六进制）
- `%d` → `120`（十进制）
- `%c` → `x`（ASCII 字符，120 对应字母 x）

数据本身没变，只是显示方式不同。

## 五、原始字节不携带自描述类型

### 5.1 内存本身知道一组字节是整数还是浮点数吗？

**不知道。** 原始字节不会自行记录“我是整数”或“我是浮点数”。C 对象仍具有声明类型或有效类型，是类型系统规定了这些字节应如何访问和解释。

同一组位在概念上可以按不同格式解释，但 **C 程序不能任意更换指针类型并解引用**。以下写法是未定义行为，可能违反有效类型、严格别名和对齐规则：

```c
int number = 0x12345678;
float *p = (float *)&number;
printf("%f\n", *p);   // ✗ 未定义行为！
```

任何对象都可以通过 `unsigned char *` 安全地观察其字节表示：

```c
const unsigned char *bytes = (const unsigned char *)&number;
// bytes[0], bytes[1], ... 逐字节读取是安全的
```

如果确实需要把同一个位模式解释为 `float`，使用 `memcpy`：

```c
#include <stdint.h>
#include <string.h>

uint32_t bits = UINT32_C(0x12345678);
float value;

_Static_assert(sizeof bits == sizeof value,
               "float must be 32 bits");

memcpy(&value, &bits, sizeof value);
// 结果仍依赖平台采用的浮点表示
```

这就是 C 语言灵活性和陷阱并存的地方——你可以观察内存，但不能随意用不同类型指针去"解读"它。

## 七、指针基础（02_pointers.c）

### 7.1 代码结构分析

```c
int x = 42;
int *p = &x;    // p 是指针变量，存的是 x 的地址
```

**三个关键值**（运行示例输出）：

| 表达式 | 含义 | 示例值 | 说明 |
|--------|------|--------|------|
| `x` | x 的值 | `42` | 普通变量存的数据 |
| `&x` | x 自己的地址 | `0x16f586458` | x 在内存中的位置 |
| `p` | 指针 p 的值 | `0x16f586458` | p 存的就是 x 的地址 |
| `&p` | p 自己的地址 | `0x16f586450` | p 本身也在内存中，有自己的地址 |
| `*p` | p 指向的值 | `42` | 解引用：去 p 存的地址里拿数据 |
| `sizeof p` | 指针变量的大小 | `8` | 当前 Apple Silicon macOS 上 sizeof(p) == 8 |

**关键理解**：指针变量 p 自己也有地址（`&p`），它和它指向的变量 x 是**两个独立的变量**，只是 p 里面存了 x 的地址而已。

### 7.2 通过指针修改变量

```c
*p = 99;   // 去 p 存的地址，修改那个地址里的值 → x 从 42 变成 99
```

运行后 `x = 99`，`*p = 99`。`*p` 就是"去 p 存的地址那里，操作那个地址里的值"，所以 `*p = 99` 等价于 `x = 99`。

### 7.3 指针可以改变指向

```c
int y = 10;
p = &y;    // p 改为指向 y（p 现在存的是 y 的地址，不再是 x 的地址）
*p = 88;   // 通过 p 修改 y
```

**常见误解纠正**：
- ❌ "y 的指针指向 p" — 方向反了！
- ✓ "p 指向 y" — p 里面存了 y 的地址，p 是箭头，y 是目标

**运行结果**：`y=88, *p=88, x=99`

注意 x 还是 99，没被影响——因为 p 已经不指向 x 了，`*p = 88` 改的是 y。

**核心比喻**：指针就像一个遥控器，改指向就是换一台电视控制。原来遥控 x，换到遥控 y，x 保持原样不变。

### 7.4 指针本质总结

```
指针变量 p 的内容 = 另一个变量的地址
*p               = 那个地址里存的值
&p               = 指针变量 p 自己的地址（p 也是变量，也在内存里）

方向关系：p ──指向──→ 目标变量
         指针         被指向的数据
```

| 操作 | 含义 | 影响谁 |
|------|------|--------|
| `p = &x` | 让 p 指向 x | 只改变 p 的值 |
| `p = &y` | 让 p 改指向 y | 只改变 p 的值 |
| `*p = 99` | 通过 p 修改目标 | 改变 p 当前指向的变量 |
| `x = 99` | 直接修改 x | 改变 x |

### 7.5 什么不能修改？

普通变量 `int x` 可以随时重新赋值（`x = 4` 完全没问题），但以下情况**不能修改**：

#### 1. 数组名不能重新赋值

```c
int arr[5] = {1, 2, 3, 4, 5};
arr = ???;   // ✗ 编译错误！
```

**`arr` 不是"常量指针"**，它是数组对象，类型是 `int [5]`。不能赋值的原因不是"它是常量指针"，而是数组表达式不是可修改左值。

两者的本质区别用 `sizeof` 就能看出来：

```c
int arr[5];
int *p = arr;

sizeof(arr); // 整个数组的大小，通常 20
sizeof(p);   // 指针变量的大小，当前机器为 8
```

在大多数表达式中，`arr` 会**自动转换**为 `&arr[0]`（类型 `int *`），但它本身不是指针对象。

#### 2. const 变量不能改

```c
const int x = 10;
x = 20;      // ✗ 编译错误！const 保护了值
```

#### 3. 字符串字面量不能改

```c
const char *s = "hello";  // 正确：用 const char * 指向字符串字面量
s[0] = 'H';               // ✗ 编译器拒绝：不能通过 pointer-to-const 修改目标
```

> **注意**：旧式 C 允许 `char *s = "hello"`（不加 const），此时即使编译通过：
> ```c
> char *s = "hello";
> s[0] = 'H';  // 实际修改字符串字面量仍是未定义行为
> ```
> 不一定表现为"运行崩溃"，也可能暂时看似成功。因此不能以是否崩溃来判断是否合法。

如果用字符数组就可以：
```c
char s[] = "hello";
s[0] = 'H';  // ✓ 可以，数组可读写
```

**为什么有这种区别？**

| 写法 | 存储期与可修改性 |
|------|-----------------|
| `const char *s = "hello"` | 指向字符串字面量，通常位于只读区域，不可修改 |
| `char s[] = "hello"` | 字符数组，具有自动存储期，可读写 |

C 标准描述的是存储期和可修改性，不直接规定一定放在哪个物理区域。字符串字面量通常在只读数据区域，函数里的普通字符数组通常在栈上。

#### 4. 通过指针修改 const 数据是危险的

```c
const int x = 10;
int *p = &x;   // ✗ 约束违反，编译器必须给出诊断
```

即使使用强制转换压掉诊断：
```c
int *p = (int *)&x;
*p = 20;       // 未定义行为！修改 const 对象
```

正确做法是使用"指向 const 的指针"，保留目标对象的 const 限定：
```c
const int x = 10;
const int *q = &x;   // q 是"指向 const int 的指针"，q 本身可以改指向
*q = 20;             // ✗ 编译错误！不能通过 pointer-to-const 修改目标
```

> **术语区分**：
> ```c
> int x = 10;
>
> const int *p1 = &x;       // 可以改指向，不能通过 p1 修改 x
> int *const p2 = &x;       // 不能改指向，可以通过 p2 修改 x
> const int *const p3 = &x; // 既不能改指向，也不能通过 p3 修改 x
> ```

**总结**：普通变量随便改，`const` 变量、字符串字面量不能改。数组名不是"常量指针"——它是数组对象，在大多数表达式中会自动转换为指向首元素的指针，但它本身不是指针。

### 7.6 WORKBOOK 核心三问

#### Q1: `p`、`&p`、`*p` 各自是什么值？

| 表达式 | 含义 | 示例值 | 类比 |
|--------|------|--------|------|
| `p` | 指针 p 存的内容（x 的地址） | `0x16f586458` | 遥控器存的红外编码 |
| `&p` | 指针变量 p 自己的地址 | `0x16f586450` | 遥控器本身在抽屉里的位置 |
| `*p` | 去 p 存的地址里拿值（x 的值） | `42` | 按下遥控器，电视显示的内容 |

**关键**：p 自己也是一个变量，有自己的内存位置（`&p`），只是它里面存的是别人的地址。

#### Q2: 执行 `*p = 99` 修改的是 `p` 还是 `x`？

修改的是 **x**，不是 p。

```
*p = 99
 ↓
解引用：去 p 存的地址（0x16f586458，即 x 的地址）
       把那个地址里的值改成 99
       → x 从 42 变成 99
       → p 本身的值（存的地址）没变
```

`*p = 99` 等价于 `x = 99`。p 仍然指向同一个地址，只是那个地址里的内容变了。

#### Q3: 为什么 `int *p` 中的 `int` 很重要？

`int` 告诉编译器两件事：

**① 解引用时读多少字节**

```c
int *p = &x;
*p   // 从 p 存的地址开始，读 sizeof(int) = 4 个字节
```

不同类型的指针，读的字节数不同：

| 指针类型 | `*p` 读取字节数 |
|----------|:---:|
| `char *` | 1 |
| `short *` | 2 |
| `int *` | 4 |
| `double *` | 8 |

**② 指针运算时的步长**

```c
int *p;
p + 1   // 不是地址 +1，而是地址 + sizeof(int) = +4 字节

char *q;
q + 1   // 地址 + sizeof(char) = +1 字节
```

类型决定了指针的"视野宽度"（一次读多少）和"移动步幅"（跳多远）。这就是为什么不能把 `int *` 直接赋给 `double *`——类型不匹配会导致解读错误。

**补充：`*p` 不总是真正读取内存**

`*p` 是一个左值表达式，不一定立即读取或写入：

```c
int value = *p;      // 从目标读取
*p = 10;             // 向目标写入
sizeof(*p);          // 不读取、不写入！sizeof 不求值，只根据表达式类型计算
&p[0];               // 取得地址，不读取元素值
```

这个特性常用于安全分配内存：

```c
int *p = malloc(10 * sizeof(*p));  // sizeof(*p) 不会解引用 p，只计算 sizeof(int)
```

### 7.7 指针合法性检查表

每次看到 `*p`（解引用），固定问自己这六个问题：

```
1. p 初始化了吗？           → 未初始化的指针是野指针
2. p 是 NULL 吗？           → 解引用 NULL 是未定义行为
3. p 指向的对象还活着吗？    → 指向已释放/已离开作用域的变量是悬垂指针
4. p 的类型和目标对象匹配吗？ → 类型不匹配可能违反严格别名
5. 地址满足该类型的对齐要求吗？ → 未对齐访问在某些平台上会崩溃
6. 本次访问有没有越界？      → 数组越界是最常见的内存错误
```

### 7.8 指针的精确表述

"遥控器"类比适合入门理解，但最终应能准确口述：

```
p 是一个 int * 类型的对象；
p 保存 x 的地址；
*p 是通过该地址访问 x 的左值表达式；
*p = 99 向 x 的存储写入 99；
p 本身保存的地址没有改变。
```

## 八、数组基础（03_arrays.c）

你确实把"数组名在多数表达式中会转换为首元素地址"理解成了"数组名永远就是首元素地址"。

正确结论是：

> `values` 本身是一个数组对象，不是指针；只是在大多数表达式中，它会自动转换为指向首元素的指针。

你的数组是：

```c
int values[4] = {10, 20, 30, 40};
```

`values` 的真实类型是：

```c
int [4]
```

也就是"包含 4 个 `int` 的数组"。

### 先区分三个表达式

```c
values
&values[0]
&values
```

假设数组从地址 `0x1000` 开始，`int` 占 4 字节：

```text
values 数组对象
起始地址 0x1000，总大小 16 字节

0x1000        0x1004        0x1008        0x100c
┌──────────┬──────────┬──────────┬──────────┐
│    10    │    20    │    30    │    40    │
└──────────┴──────────┴──────────┴──────────┘
 values[0]   values[1]   values[2]   values[3]
```

三个表达式的关系：

| 表达式 | 类型 | 指向什么 | 地址数值 |
|---|---|---|---|
| `values` | 通常转换为 `int *` | 第一个 `int` | `0x1000` |
| `&values[0]` | `int *` | 第一个 `int` | `0x1000` |
| `&values` | `int (*)[4]` | 整个数组 | `0x1000` |

它们的地址数值相同，是因为：

- 第一个元素从 `0x1000` 开始
- 整个数组也从 `0x1000` 开始

但它们的类型和指向对象不同。

可以想象成一栋楼：

```text
&values     = 整栋楼的入口
&values[0]  = 第一个房间的入口
```

整栋楼和第一个房间可以从同一个位置开始，但"整栋楼"和"第一个房间"显然不是同一个对象。

### 为什么 `sizeof values` 是数组大小

数组到指针的转换有几个例外，其中最重要的是：

```c
sizeof values
&values
```

在 `sizeof` 和一元取地址运算符 `&` 中，数组不会转换为首元素指针。

所以：

```c
sizeof values
```

计算的是整个数组：

```c
4 * sizeof(int)
```

当前机器上：

```c
sizeof values == 16
```

而如果先让数组转换成指针：

```c
int *p = values;

sizeof p
```

计算的是指针对象大小：

```c
sizeof p == 8 // 当前 Mac
```

比较：

```c
sizeof values     // 16，整个数组
sizeof values[0]  // 4，一个 int
sizeof &values[0] // 8，一个 int * 指针
sizeof &values    // 8，一个 int (*)[4] 指针
```

注意：

```c
sizeof &values[0] == sizeof &values
```

只表示这两种指针在当前平台大小相同，并不表示它们类型相同。

### 为什么 `values + 1` 与 `&values + 1` 不一致

你说得完全正确：指针加一必须考虑步长。

规则是：

> 指针 `+1`，移动一个"所指对象"的大小。

#### `values + 1`

在这个表达式中，`values` 自动转换为：

```c
int *
```

它指向一个 `int`，所以步长是：

```c
sizeof(int) == 4
```

因此：

```text
values      = 0x1000
values + 1  = 0x1004
```

它指向：

```c
&values[1]
```

也就是第二个元素。

#### `&values + 1`

`&values` 的类型是：

```c
int (*)[4]
```

读作：

> 指向"包含 4 个 int 的数组"的指针。

它指向的对象是整个数组，因此步长是：

```c
sizeof(int[4])
= 4 * sizeof(int)
= 16
```

所以：

```text
&values      = 0x1000
&values + 1  = 0x1010
```

它指向整个数组的尾后位置。

对比：

```text
values + 1
0x1000 + sizeof(int)
= 0x1004

&values + 1
0x1000 + sizeof(int[4])
= 0x1010
```

### 一张完整对照表

假设首地址是 `0x1000`：

| 表达式 | 类型 | 步长 | 结果地址 |
|---|---|---:|---:|
| `values` | 转换为 `int *` | 4 | `0x1000` |
| `values + 1` | `int *` | 4 | `0x1004` |
| `values + 4` | `int *` | 4 | `0x1010` |
| `&values[0]` | `int *` | 4 | `0x1000` |
| `&values[0] + 1` | `int *` | 4 | `0x1004` |
| `&values` | `int (*)[4]` | 16 | `0x1000` |
| `&values + 1` | `int (*)[4]` | 16 | `0x1010` |

因此下面两个结果地址相同：

```c
values + 4
&values + 1
```

但类型仍然不同：

```c
values + 4   // int *
&values + 1  // int (*)[4]
```

它们都表示尾后位置，不能解引用。

### `values[i]` 为什么等于 `*(values + i)`

```c
values[i]
```

按照 C 的定义相当于：

```c
*(values + i)
```

以 `values[2]` 为例：

```text
values 转为 int *，地址为 0x1000
values + 2 移动两个 int，即 8 字节
得到地址 0x1008
*(values + 2) 读取该地址的 int
结果为 30
```

因此：

```c
values[2] == *(values + 2)
```

### `&values` 怎么读

这种声明第一次看容易晕：

```c
int (*p)[4] = &values;
```

从变量名 `p` 向外读：

```text
p
(*p)       p 是指针
(*p)[4]    p 指向一个包含 4 个元素的数组
int        数组元素类型是 int
```

所以：

```c
p == &values
```

通过它访问元素可以写：

```c
(*p)[0] // 10
(*p)[1] // 20
```

这里括号不能省略：

```c
(*p)[1] // 先解引用整个数组，再取第 2 个元素
*p[1]   // 等价于 *(p + 1)，意思完全不同
```

### 最终记忆模型

不要记：

```text
values 就是首元素地址
```

应该记：

```text
values 是一个 int[4] 数组对象。

在大多数表达式中：
values 自动转换为 &values[0]，类型为 int *。

在 sizeof values 中：
不转换，计算整个数组大小。

在 &values 中：
不转换，取得整个数组的地址，类型为 int (*)[4]。

values + 1：
移动一个 int。

&values + 1：
移动一个 int[4]，也就是整个数组。
```

你当前 `03_arrays.c:22` 的预测注释里：

```c
// 4, 8 // 数组总大小16，单个元素大小4
```

正确输出应该直接记为：

```c
// sizeof values == 16
// sizeof values[0] == 4
```

而 `03_arrays.c:29` 的地址应理解为首地址增加 4 字节，例如：

```text
values     = 0x1000
values + 1 = 0x1004
```

不是在十六进制字符串末尾简单拼一个 `4`，而是对地址做十六进制加法。
