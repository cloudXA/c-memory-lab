## 一、printf 格式占位符

### 1.1 `%02x` 是什么意思？（第 8 行 `printf("%02x ", bytes[i])`）

`%02x` 拆解：
- `%x` — 以十六进制格式输出（小写字母 a-f）
- `02` — 最小宽度 2 位，不足时左边补 0

**举例对比**：

| 字节值（十进制） | `%x` 输出 | `%02x` 输出 |
|:---:|:---:|:---:|
| 10 | `a` | `0a` |
| 255 | `ff` | `ff` |
| 0 | `0` | `00` |

这样每个字节始终显示为整齐的 2 位十六进制数，方便查看内存原始数据。

### 1.2 `%p`、`%zu`、`%c`、`%#x`、`%.2f` 分别是什么意思？（第 20-22 行）

```c
printf("letter     %p   %zu     %c\n",   (void *)&letter, sizeof letter, letter);
printf("number     %p   %zu     %#x\n",  (void *)&number, sizeof number, number);
printf("decimal    %p   %zu     %.2f\n", (void *)&decimal, sizeof decimal, decimal);
```

| 占位符 | 参数类型要求 | 含义 | 示例输出 |
|--------|-------------|------|----------|
| `%p` | `void*`（必须显式转换） | 打印内存地址（十六进制） | `0x16b0a30f0` |
| `%zu` | `size_t` | 打印 `sizeof` 返回值 | `4` |
| `%c` | `int`（char 会整型提升） | 打印单个 ASCII 字符 | `A` |
| `%#x` | `unsigned int` | 带 `0x` 前缀的十六进制 | `0xff` |
| `%.2f` | `double`（float 会提升） | 保留 2 位小数的浮点数 | `3.14` |

> **注意**：`%p` 期望的是 `void*`，所以要把 `&letter`（类型是 `char*`）显式转换成 `(void*)`，否则属于未定义行为。

### 1.3 `(void *)&letter` 加这个转换是什么意思？

- `&letter` — 取 letter 的地址，类型是 `char*`
- `(void *)&letter` — 把 `char*` 转成通用的 `void*` 类型

因为 `%p` 严格要求参数是 `void*` 类型，虽然大多数编译器不报错，但类型不匹配在 C 标准中属于未定义行为。加上显式转换可以消除警告，也是标准写法。

## 二、小端序（Little Endian）

### 2.1 为什么 0x12345678 打印出来是 78 56 34 12？（第 7-9 行循环）

因为你的 Mac 是**小端序**架构（x86-64）。

**小端序规则**：最低有效字节（LSB）存在最低内存地址。

```
值:    0x12  34  56  78
       高位            低位（LSB）

内存地址  低  → → → → → → → →  高
存储字节  78      56      34      12
         低位                      高位
```

循环从低地址往高地址读，所以先读到 `78`，然后 `56`、`34`、最后 `12`。

**大小端对比**：

| 架构 | 0x12345678 内存排列 | 代表平台 |
|------|-------------------|---------|
| 小端序 | `78 56 34 12` | x86、x86-64、大多数 ARM |
| 大端序 | `12 34 56 78` | 某些嵌入式处理器、网络字节序 |

### 2.2 为什么是 78 56 而不是 7 8 5 6？

因为 **CPU 寻址的最小单位是 1 个字节（8 比特）**，不能只读半个字节。

```
0x78 = 0111 1000 （这是一个完整的字节）
       ↑     ↑
      7     8     两个十六进制位合在一起才是一个字节
```

一个十六进制位 = 4 比特，所以 1 字节 = 2 个十六进制位。`0x78` 是一个整体，不能拆成 `0x7` 和 `0x8` 来单独读取。

### 2.3 number = 256 时，为什么是 00 01 00 00？

```
256 = 0x100 = 0x00000100（4 字节 int，高位补零）

内存排列（小端序）：
地址  低 → → → → → 高
字节  00   01   00   00
      LSB           MSB
```

- 字节 0（最低位）：`0x00`
- 字节 1：`0x01`（1 × 256 = 256，进位到这里了）
- 字节 2、3：`0x00`（高位补零）

### 2.4 -1 的十六进制是什么？

`-1` 在 4 字节 int 中是 `0xFFFFFFFF`，小端序排列为 `ff ff ff ff`。

**原因 — 补码（Two's Complement）**：

```
 1  = 0x00000001
~1  = 0xFFFFFFFE   （按位取反）
+1  = 0xFFFFFFFF   （加一，这就是 -1）

验证：-1 + 1 = 0
0xFFFFFFFF + 0x00000001 = 0x00000000  ✓（进位溢出丢弃）
```

**4 字节 int 值域**：

| 值 | 十六进制 | 说明 |
|----|----------|------|
| 2147483647 | `0x7FFFFFFF` | 最大正数 |
| 1 | `0x00000001` | |
| 0 | `0x00000000` | |
| -1 | `0xFFFFFFFF` | 全 1 |
| -2147483648 | `0x80000000` | 最小负数 |

**判断正负的快捷方式**：最高位是 0 → 正数/零，最高位是 1 → 负数。

## 三、unsigned char* 逐字节读取技巧

### 3.1 循环怎么知道读几个字节？为什么一个地址刚好对应一个字节？

```c
for (size_t i = 0; i < size; ++i) {
    printf("%02x ", bytes[i]);
}
```

**循环次数**由 `size` 参数决定，调用时传的是 `sizeof number`（int 是 4），所以循环 4 次。

**一个地址一个字节**是因为 `unsigned char*` 的指针步长是 1：

```c
// C 标准规定：sizeof(unsigned char) == 1 恒成立
```

**指针运算公式**：`ptr + i` 的实际地址 = `原始地址 + i × sizeof(指针指向的类型)`

| 指针类型 | `ptr + 1` 跳多少字节 |
|----------|---------------------|
| `int*` | 4 字节 |
| `char*` / `unsigned char*` | 1 字节 |
| `double*` | 8 字节 |

所以把 `&number`（int*）转成 `unsigned char*` 后，`bytes[0]` 读第 1 个字节，`bytes[1]` 读第 2 个字节，每次刚好前进 1 字节。

## 四、十六进制与二进制的关系

### 4.1 为什么查看内存都用十六进制而不是十进制？

因为十六进制和二进制**天然对齐**：

```
1 字节 = 8 比特
1 个十六进制位 = 4 比特
所以 1 字节 = 2 个十六进制位
```

**对照表**：

| 十六进制 | 二进制 | 十进制 |
|:---:|:---:|:---:|
| `0x0` | 0000 | 0 |
| `0x5` | 0101 | 5 |
| `0xA` | 1010 | 10 |
| `0xF` | 1111 | 15 |
| `0xFF` | 1111 1111 | 255 |

看 `0xFF` 就知道 8 个比特全是 1；看十进制 `255` 完全看不出位模式。所以查看内存原始数据时，十六进制是最直观的选择。

### 4.2 输出前是先转成了十六进制吗？

对，`%02x` 就是告诉 `printf`："把这个整数值用十六进制格式显示"。

```
内存原始数据（二进制）
      ↓
bytes[i] 读出一个字节值（比如 120）
      ↓
%02x 格式化成字符串 "78"
      ↓
屏幕显示: 78
```

同一个值 120，不同格式输出不同：
- `%02x` → `78`（十六进制）
- `%d` → `120`（十进制）
- `%c` → `x`（ASCII 字符，120 对应字母 x）

数据本身没变，只是显示方式不同。

## 五、内存无类型 — 核心哲学

### 5.1 内存本身知道一组字节是整数还是浮点数吗？

**不知道。** 内存就是一堆无意义的字节。是**类型系统**赋予了它们含义。

同一段内存 `78 56 34 12` 可以有不同解读：

```
用 int* 读取     → 0x12345678（整数 305419896）
用 float* 读取   → 约 5.69e-28（按 IEEE 754 解码）
用 char[4] 读取  → 'x' 'V' '4' '\x12'（4 个 ASCII 字符）
```

这就是 C 语言灵活性的根源——你可以用不同的"视角"（指针类型）去解读同一段内存，但也因此容易写出 bug。

## 六、快速参考

### sizeof 常见值（macOS/Linux x86-64）

| 类型 | 大小 |
|------|:---:|
| char | 1 |
| short | 2 |
| int | 4 |
| long | 8 |
| long long | 8 |
| float | 4 |
| double | 8 |
| 指针（任何类型） | 8 |

> `sizeof` 是编译时运算符，不是函数。`sizeof(char)` 恒为 1（C 标准强制）。
