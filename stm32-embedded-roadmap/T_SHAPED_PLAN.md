# STM32 T 型学习执行表

## 1. T 型学习是什么

```text
横向广度：GPIO 时钟 EXTI 定时器 UART I2C SPI ADC DMA 看门狗 RTOS
──────────────────────────────────────────────────────────────
                         │
                         │ UART 纵向主线
                         │
                         ├─ C 指针、数组和生命周期
                         ├─ 时钟、波特率和 GPIO 复用
                         ├─ 中断与 NVIC
                         ├─ 环形缓冲区
                         ├─ 命令协议与状态机
                         ├─ DMA 与可变长接收
                         ├─ FreeRTOS 队列
                         └─ 测量、故障恢复与工程化
```

横向让你看懂完整系统并知道去哪里查；纵向让你具备独立解决真实问题的能力。

## 2. 横向模块的停止标准

横向学习不是“只听过名词”，但也不要求第一次就精通。每个模块达到以下条件即可暂时停止下钻：

```text
知道它解决什么问题
能画出基本数据/控制路径
会用 CubeMX 配置最小工程
能运行一个可观察实验
能修改一个关键参数并预测结果
知道三种常见故障
知道查哪份官方手册、用什么工具验证
```

| 模块 | 横向实验 | 暂时不用深入 |
|---|---|---|
| GPIO | LED、按键、消抖 | 所有端口寄存器细节 |
| 时钟 | HSI/HSE/PLL 和总线频率 | 晶振模拟电路设计 |
| EXTI/NVIC | 按键中断 | Cortex-M 异常全部细节 |
| 定时器 | 周期中断和 PWM | 所有高级定时器模式 |
| I2C | 读取一个传感器 | 完整从机协议栈 |
| SPI | 读取设备 ID | 所有器件私有协议 |
| ADC | 单次采样和 DMA | 高精度模拟前端设计 |
| 看门狗 | 故意卡死并复位 | 复杂安全认证机制 |
| Flash | 保存一份带校验参数 | 完整文件系统 |
| FreeRTOS | 任务、队列、通知 | 调度器内核源码 |

## 3. UART 纵向主线

### 阶段 1：阻塞收发

知识：GPIO 复用、USART 时钟、波特率、帧格式、TX/RX 和共地。

产物：电脑发送字符，STM32 原样返回。

验收：

- 能解释波特率从哪个时钟计算；
- 能用逻辑分析仪确认线上字节；
- 改错波特率后能预测并解释乱码。

### 阶段 2：中断接收

知识：NVIC、IRQHandler、HAL 回调、中断上下文和快速 ISR。

产物：中断接收字节，主循环处理。

验收：

- 能画出引脚到回调的路径；
- 回调中不做阻塞业务；
- 知道为什么接收完成后需要重新启动。

### 阶段 3：环形缓冲区

知识：数组、指针、`head/tail/count`、生产者消费者、溢出策略。

产物：持续输入时字节进入环形缓冲区，主循环逐步消费。

验收：

- 空、满、绕回测试通过；
- 快速输入不会越界；
- 溢出有计数并执行明确策略。

### 阶段 4：命令协议

知识：帧头、长度、命令、载荷、校验、半包、粘包、噪声重同步。

产物：通过串口控制 LED、PWM 和查询状态。

验收：

- 一个字节一个字节输入也能解析；
- 错误帧后能恢复；
- 长度字段不能造成越界；
- 未知命令返回错误而不是卡死。

### 阶段 5：DMA 与空闲线

知识：DMA 请求、传输宽度、缓冲区生命周期、半完成/完成/空闲事件。

产物：DMA 接收可变长数据并送入协议层。

验收：

- 能说明 DMA 使用哪块内存；
- DMA 期间缓冲区不会失效或被无同步覆盖；
- 压力输入下统计丢包和溢出；
- 知道 DMA 解决的是搬运开销，不自动解决协议问题。

### 阶段 6：FreeRTOS 通信任务

知识：任务状态、队列、任务通知、ISR `FromISR` API、任务栈。

产物：UART ISR/DMA 把事件交给通信任务，通信任务解析并向业务任务发消息。

验收：

- 不通过裸全局变量传递完整消息；
- 能说明数据所有权；
- 记录任务栈高水位；
- 高优先级任务会阻塞等待事件，不空转占满 CPU。

### 阶段 7：工程化与故障恢复

知识：模块接口、状态机、超时、错误码、日志、看门狗、测试。

产物：可复现的设备控制台或传感器终端。

验收：

- 业务代码不散落 HAL 调用；
- 串口拔插、噪声和压力输入可恢复；
- README 包含数据流、时钟计算和测试证据；
- 能脱离视频和 AI 重建最小链路。

## 4. 每周广度与深度比例

初期：

```text
横向 70%：建立 GPIO、时钟、定时器、通信地图
纵向 30%：保持 UART 基础链路持续演进
```

中期：

```text
横向 50%：补齐 I2C、SPI、ADC、DMA
纵向 50%：环形缓冲区、协议和 DMA
```

项目期：

```text
横向 20%：按项目需要补知识
纵向 80%：集成、排错、测试和文档
```

这不是严格工时比例，而是防止“只看模块不做项目”或“陷入一个寄存器不再前进”。

## 5. 什么时候应该下钻

满足任一条件时下钻：

- 当前模块位于 UART 主线；
- 综合项目反复使用；
- 出现无法用 API 层解释的故障；
- 目标岗位明确要求；
- 性能、实时性或可靠性不足；
- 需要从 HAL 下钻到寄存器和波形获得证据。

## 6. 什么时候停止下钻

出现以下情况时先返回主线：

- 正在阅读与当前实验无关的所有寄存器；
- 为了“彻底理解”开始研究暂时用不到的内核源码；
- 连续多天没有新的可运行产物；
- 细节无法连接到现象、故障或项目需求；
- 只是记忆 API/位定义，没有测量和验证。

记录问题，等真实项目需要时再深入，不等于放弃。

## 7. AI 在 T 型学习中的位置

AI 可以帮助横向快速建立地图，也可以在纵向提供候选代码，但不能替代验证：

```text
AI 候选方案
  ↓
官方手册核对
  ↓
编译与调试
  ↓
开发板运行
  ↓
逻辑分析仪/示波器测量
  ↓
故障注入
  ↓
脱离 AI 重建
```

横向阶段可以更多依赖 AI 做索引和解释；纵向主线必须逐渐减少对 AI 生成核心代码的依赖。

## 8. 求职完成标准

横向：GPIO、时钟、定时器、UART、I2C、SPI、ADC、DMA、FreeRTOS 都能说明用途、最小配置和常见故障。

纵向：能够从 UART 引脚开始，一路讲清并实现：

```text
引脚与时钟
→ USART
→ IRQ/DMA
→ 缓冲区
→ 协议
→ 状态机
→ RTOS 任务
→ 错误恢复
→ 仪器验证
```

项目：至少一个综合项目具备源码、`.ioc`、接线图、README、测试记录、故障恢复和演示视频。

达到以上条件，比“看完所有外设视频”更接近初级嵌入式岗位的真实要求。
