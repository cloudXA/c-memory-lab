# STM32 调试与故障定位

## 固定排查顺序

遇到“没反应”不要立即重建工程，按层排查：

```text
供电与接线
  ↓
下载器是否识别芯片
  ↓
程序是否进入 main
  ↓
时钟是否正确
  ↓
外设时钟和引脚复用
  ↓
初始化参数
  ↓
启动 API 是否调用
  ↓
中断/DMA 标志与回调
  ↓
业务状态机和缓冲区
```

## 最小调试工具箱

- 编译器警告：保持高警告等级，不能把警告当正常输出；
- ST-LINK/SWD：断点、单步、寄存器和内存查看；
- 串口日志：记录状态和错误码，不代替断点；
- 万用表：电压、通断和静态电平；
- 逻辑分析仪：UART/I2C/SPI/PWM 时序；
- 示波器：模拟波形、边沿、噪声和精确时序；
- map 文件：Flash/RAM 占用和符号位置。

## 断点与观察

需要掌握：

- 普通断点和条件断点；
- Watch 表达式；
- Memory View；
- Peripheral/Register View；
- Call Stack；
- 反汇编与源码混合视图；
- 数据观察点 Watchpoint（硬件数量有限）。

不要在严格时序或中断问题中随意断点，因为暂停 CPU 会改变现场。此时优先使用 GPIO 翻转、环形日志或逻辑分析仪。

## HardFault 基本模型

常见原因：

- 空指针、野指针、悬空指针；
- 数组越界破坏栈；
- 栈溢出；
- 未对齐或非法地址访问；
- 错误函数指针；
- 异常返回现场损坏；
- 某些总线/外设访问错误。

排查要点：

1. 在 `HardFault_Handler` 断点；
2. 查看 Call Stack，但栈破坏时不要完全相信；
3. 查看故障状态寄存器；
4. 找到异常入栈的 PC/LR；
5. 对照 map/反汇编定位指令；
6. 检查指针、数组长度和任务栈高水位。

不同 Cortex-M 型号可用的故障寄存器不同，以编程手册为准。

## UART 没数据

检查：

- TX/RX 是否交叉；
- 是否共地；
- TTL 电平是否兼容；
- USART 实例和引脚复用；
- 外设时钟和波特率时钟；
- 波特率、数据位、停止位和校验；
- HAL 返回值是否为 `HAL_OK`；
- 中断接收是否重新启动；
- DMA/IRQ 是否启用且优先级合理。

## I2C 找不到设备

检查：

- SDA/SCL 上拉和静态高电平；
- 7 位地址与 HAL 参数格式；
- 设备电源、复位和模式引脚；
- 逻辑分析仪是否看到 START、地址和 ACK；
- 总线是否被某设备一直拉低；
- 超时后是否需要恢复总线。

## 定时器/PWM 频率不对

检查：

- 定时器实际输入时钟；
- APB 分频与定时器倍频规则；
- `PSC + 1`、`ARR + 1`；
- 计数模式；
- 通道是否启动；
- GPIO 复用；
- 用逻辑分析仪/示波器测量，而不是只看 LED 肉眼效果。
